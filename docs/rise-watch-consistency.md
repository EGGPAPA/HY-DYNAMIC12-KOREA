# 상승시점 A/B 관찰과 알림

## 공통 판정

화면과 `scripts/monitor_rise_watchlist.py`는 KIS 자료와
`rise_live_analysis.evaluate_current`를 사용한다. 과거 Yahoo 일봉의 최근
3일 최대 거래량은 사용하지 않는다. 거래량은 당일 누적 거래량을 직전
20거래일 하루 평균으로 나눈 값이다.

알림은 정규장 현재가 평가에서 필수 4개(가격거리·거래량·돌파·손절위험)를
모두 충족하고 보조 3개 중 1개 이상을 충족할 때 가능하다. 과열·평가 보류·
종가 참고는 알림 대상이 아니다. 이 조건은 `entry_signal` 한 곳에서 관리한다.

지속성은 필수 조건이 모두 유지되는 서로 다른 두 관측으로 확인한다.
관측 간격은 10~60초이며 조건 이탈, 시세 실패, 거래일 변경, 긴 관측 공백은
기록을 초기화한다. 서버는 실행마다 새 시세를 두 번 확인하며 과거 충족
날짜를 누적해 지속성으로 인정하지 않는다.

## 같은 관찰 대상

`rise_watch_policy.watch_groups`가 화면과 서버의 A+B 목록을 만든다.
A는 최신 확정 일봉의 초기 후보, B는 기존에 선정해 계속 추적하는 종목이다.
B의 조건 약화는 삭제 사유가 아니다. 현재 상태를 상승 지속·조건 약화·
평가 보류로 구분한다. A와 B에 같은 종목을 중복 표시하지 않는다.

선정자료는 KIS가 확인한 최근 확정 거래일과 일치해야 한다. 거래일을
확인하지 못할 때에는 최대 4일의 보수적인 유효기간을 적용한다. 오래되거나
미완료인 자료에서는 A를 선정하지 않고 B를 평가 보류로 유지한다.

통합 화면에는 A 최대 20개와 B 최대 20개를 함께 표시한다. 그룹 선택은
한 표를 필터링하므로 같은 B 표를 중복 렌더링하지 않는다.

## 검색과 운영 상태

전체시장 검색은 백그라운드에서 진행하며 30개 이하의 시세 묶음을 받는
즉시 평가한다. 순차 검색의 상위 20개를 화면에 표시하거나 알리기 전에
현재가를 다시 조회한다. 전체 재검색은 분석 버튼으로 시작한다.

GitHub Actions는 한국 정규장 중 15분 간격으로 예약하지만 실행 시각을
보장하지 않는다. 화면은 마지막 정상 평가, 일부 자료 실패, 전송 실패와
25분 이상 갱신 지연을 표시한다. 장외 실행을 정상 시장 평가로 기록하지 않는다.

서버 실행에는 GitHub Actions의 `KIS_APP_KEY`, `KIS_APP_SECRET`,
`KAKAO_REST_API_KEY`, `KAKAO_REFRESH_TOKEN` 설정이 필요하다.
`KAKAO_CLIENT_SECRET`은 사용 계정에 설정된 경우 제공한다. 값은 코드나
상태 파일에 기록하지 않는다. KIS 인증 실패는 Yahoo로 대체하지 않고 보류한다.
KIS 비밀값이 누락되면 외부 시세 조회와 알림 전송을 시작하지 않고, 설정이
필요한 키 이름만 운영상태에 기록한다. Streamlit 앱의 Secrets와 GitHub
Actions의 저장소 Secrets는 별도이므로 양쪽에 같은 KIS 설정이 필요하다.

카카오 HTTP 응답과 `result_code == 0`을 모두 확인한 뒤 거래일·종목별
전송 완료를 기록한다. 실패 건은 다음 실행에서 현재 조건을 다시 확인한
뒤 재시도한다. 수신 성공 직후 상태 저장이 실패하는 경우는 두 외부 서비스의
원자적 처리가 불가능하므로 중복 가능성이 남는다.

`python scripts/monitor_rise_watchlist.py --dry-run`은 읽기·평가만 수행하며
메시지를 보내거나 원격 상태를 저장하지 않는다. 수동 workflow 실행은
기본적으로 dry run이다. 장외 조회에는 `FORCE_RUN=true`를 사용하되
휴일 종가 참고를 실시간 알림으로 바꾸지 않는다.

40종목 표시를 확인한다. 모든 테스트의 시세·전송은 모의 자료이다.
