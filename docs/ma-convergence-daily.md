# 5·20·60일선 수렴 일일 관찰

이 기능은 **수렴 차트 후보를 찾는 관찰 기능**이며, 백테스트로 검증된 매수 신호가 아닙니다.
하락 중에도 세 선이 모일 수 있습니다. 기존 상승시점 점수·필수조건·KIS 현재가 로직은 바꾸지 않습니다.

## 검색 및 추가

- 한국시간 평일 20:30 GitHub Actions 서버 실행. PC/앱이 꺼져 있어도 실행됩니다. GitHub 사정에 따라 지연되거나 실행되지 않을 수 있으므로 최근 기준일을 확인하세요.
- 실행일의 20:15 이전에는 전일까지만 사용합니다. 삼성전자·SK하이닉스의 최신 일봉 날짜가 일치해야 처리합니다. 이전 완료 기준일과 같으면 휴장/중복 실행으로 보고 추가하지 않습니다.
- Naver KOSPI·KOSDAQ 목록에서 6자리 코드 주식, ETF·ETN·우선주·스팩 제외. 거래상태가 TRADING으로 확인된 종목만 자동 추가 대상입니다. 사용자 기존 등록 종목은 이 필터로 삭제하지 않습니다.
- 일봉 최소 65개, 해당 거래일 거래량 > 0, 종가 1,000원 이상, 최근 20일 평균 거래대금 5억원 이상.
- 수렴 간격 = `(max(5일선,20일선,60일선)-min(...))/세 이동평균의 평균 × 100`, **3% 이내**. 120일선은 제외합니다.
- 후보 중 최근 5거래일 대비 간격 축소 → 현재 간격 작은 순 → 거래대금 큰 순으로 신규 최대 **10개/거래일** 추가합니다. 이는 수익률 순위가 아닙니다.
- 기존 종목/사용자 필드는 그대로 보존하고 중복을 추가하지 않습니다. 이전 실행에서 등록을 확인한 종목은 사용자가 삭제하면 자동 재등록하지 않습니다. 데이터 오류 때 목록을 비우거나 예전 종가를 최신으로 표시하지 않습니다.

## 화면 및 저장

- 개인 관찰목록 동일 표에 `세 선 수렴`, `수렴 간격`, `수렴 기준일` 표시. 🔵 수렴 관찰 / 🟠 수렴 중이나 종가는 세 선 아래 / ⚪ 비수렴·자료 확인.
- 기존 상세 차트에 5일선을 추가합니다. 기존 Yahoo 차트와 새로운 Naver 확정 일봉 수렴 계산은 제공처·장중 포함 여부가 달라 수치가 다를 수 있으며 화면에 구분 표시합니다.
- `main/rise_timing_watchlist.json`: 기존 개인 관찰목록에 추가만 수행.
- `monitor-state/data/ma_convergence_daily.json`: 후보, 계산 기준일·범위·오류, 개인 목록의 수렴 값, 자동 추가 기록. 기존 15분 감시의 `rise_timing_live.json`은 건드리지 않습니다.
- 새로 추가된 종목은 페이지를 다시 열거나 새로고침하면 반영됩니다. 현재 열려 있는 표의 가격 갱신 방식은 유지합니다.
- 이 작업 자체는 주문이나 카카오 메시지를 보내지 않습니다. 기존 15분 감시/알림은 보존되며 추가 종목도 기존 감시 대상이 됩니다.

## 검증과 운영

`python -m unittest discover -s tests -p test_ma_convergence.py -v`

`python scripts/refresh_ma_convergence.py --output artifacts/convergence-dry-run.json`은 외부 데이터 읽기만 수행합니다.
실제 갱신은 Actions의 `GITHUB_TOKEN`과 `--publish`가 필요합니다. main의 최신 파일 SHA를 읽고 충돌 시 다시 병합합니다.
추가 계획을 먼저 저장하여 중간 실패 후 재시도하더라도 다음 10개가 중복 추가되지 않습니다.
종목 목록 98% 미만 수집, 가격 요청 실패 5% 초과, 계산 가능 비율 80% 미만이면 게시하지 않습니다.
일일 전체 후보 보고서는 Actions 아티팩트로 14일 보관합니다.

중지하려면 GitHub Actions → Daily MA convergence watchlist → Disable workflow.
실행 상태가 실패하면 원인을 확인한 뒤 Re-run jobs. 이미 처리한 종가 날짜는 추가를 반복하지 않습니다.
